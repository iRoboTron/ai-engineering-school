# ИИ для 9 класса

Курс из восьми тем о том, как на самом деле устроен искусственный интеллект — для школьников,
которые уже немного программируют. Простым языком, со схемами, повторениями и маленькими
лабораторными на Python. Лабораторные двух уровней: мини-версии прямо в тексте уроков
(короткие скрипты, запускаются без ключей и интернета) и ноутбуки для Google Colab
с настоящими инструментами — токенизатором `tiktoken`, разговорами с реальной моделью
через школьный сервер, поиском BM25, эмбеддингами и агентами. Ноутбуки есть во всех
восьми темах.

Сделан на основе взрослого курса `../ai-engineering` (интенсив для разработчиков): темы те же,
изложение и глубина — школьные.

## Как открыть локально

```bash
cd docs/books
python3 -m http.server 8099 --bind 127.0.0.1
```

Открыть http://127.0.0.1:8099/index.html — это каталог тем. Читалка (`reader.html`) собирает
всю тему в одну страницу: можно читать подряд, переходить по оглавлению и печатать в PDF.

Всё работает офлайн: библиотеки (marked, highlight.js, mermaid, DOMPurify) лежат в `vendor/`,
внешних CDN нет.

## Лабораторные

Практика идёт в двух видах, и это сделано намеренно.

**Мини-версии в тексте урока** (`docs/books/labs/*.py`) — короткие скрипты на стандартной
библиотеке. Ими объясняется идея: их можно прочитать целиком за минуту и запустить
без всего. Настоящую модель там заменяет заглушка, чтобы виден был механизм.

**Ноутбуки с настоящими инструментами** (`docs/books/labs/*/*.ipynb`) — то же самое,
но по-настоящему: живая модель, живые библиотеки. Открываются кнопкой в Google Colab
прямо из урока, ставить ничего не нужно. Исходники лежат в `notebooks/` как читаемые
`.py` с ячейками и собираются скриптом `scripts/build_notebooks.py`.

| Ноутбук | Что там настоящее |
|---|---|
| `tema1/01_tokeny` | токенизатор `tiktoken`: реальные токены, цена запроса, окно в страницах |
| `tema1/02_generaciya` | живая модель: роли, `finish_reason`, температура, галлюцинации |
| `tema1/03_instrumenty` | схема ответа (`response_format`) и настоящий вызов инструмента |
| `tema2/01_nastoyashchiy_rag` | поиск `rank_bm25` + ответ модели с грунтованием |
| `tema3/01_smysl_v_chislah` | эмбеддинги `multilingual-e5-small`, картинка, поиск по смыслу |
| `tema4/01_agent_s_granicami` | агент с вызовом инструментов и четырьмя границами |
| `tema5/01_izmeryaem_kachestvo` | эталонный набор, замер поиска и ответов, ИИ-судья |
| `tema6/01_podmena_instrukciy` | подмена инструкций на живой модели и три защиты |
| `tema7/01_moy_proyekt` | каркас: подставить свои документы и вопросы |
| `tema8/01_ispravlyaem_bota` | чиним бота по одной правке с замером после каждой, журнал |

Ноутбукам, которые обращаются к модели, нужен **код класса** — его выдаёт учитель.
Ключ OpenRouter хранится только на сервере (см. «Прослойка к модели»).

Ноутбуки, которые обращаются к модели, прогнаны против живой: текст уроков описывает то, что
реально выводится, включая провалы. Это принципиально — курс учит смотреть на результат,
а не на ожидания. Ноутбуки про токены и эмбеддинги работают целиком локально.

## Прослойка к модели

`proxy/` — небольшой сервис в CT 109, через который ученики обращаются к OpenRouter:

* ключ OpenRouter лежит только на сервере, у детей его нет;
* ученик шлёт **код класса** вместо ключа (`AI9_CLASS_TOKENS` в `/etc/ai9-proxy.env`);
* разрешены только дешёвые модели из списка, длина ответа ограничена;
* лимиты: 120 запросов в час на класс, 3000 в сутки на всех; расход пишется в
  `/var/log/ai9-proxy/usage.jsonl`;
* при отказе модели (у бесплатных это постоянно) автоматически берётся следующая
  из списка, чтобы урок не рвался.

Установка и обновление: `./scripts/setup-proxy.sh` (секреты вводятся без эха и в
репозиторий не попадают). Проверка: `curl https://ai9.adelfos.ru/api/health`.

Отдельно: OpenRouter отвечает отказом на запросы из РФ, поэтому контейнер резолвит
имена через DoH — `./scripts/setup-dns.sh` (профиль берётся из уже настроенного CT 120).

## Витрина моделей

**https://ai9.adelfos.ru/models.html** — личная служебная страница, из каталога курса на неё не ведёт ни одна ссылка. Цены OpenRouter и рейтинги LMArena вместе: какие модели сейчас сильные и недорогие.

* `GET /api/catalog` в прокси (браузер из РФ до OpenRouter не достучится). Каталог OpenRouter кэшируется на час (`AI9_CATALOG_TTL`), при сбое отдаётся прошлый с пометкой `stale`.
* Рейтинги — открытый датасет [LMArena](https://huggingface.co/datasets/lmarena-ai/leaderboard-dataset) (CC BY 4.0): parquet-файл качается в фоне раз в 12 часов (`AI9_ARENA_TTL`), зачёты `overall, russian, coding, math, instructions, hard, creative, multi_turn`. У каждой модели в ответе `ratings`, `arena_name` и `arena_exact`: имена LMArena сопоставлены с id OpenRouter по нормализованному имени, `false` — приблизительно (другой снимок той же линейки).
* Страница: граница выгоды (нет модели одновременно дешевле и сильнее), фильтры «понимает русский», рейтинг и голоса, цена, окно от/до, отсев старых, возможности; три графика; выгрузка CSV/JSON. Настройки хранятся в браузере.
* Для других проектов удобнее брать API напрямую: `curl https://ai9.adelfos.ru/api/catalog`.
* Локально без прокси: сохранить ответ `/api/catalog` в `docs/books/` и открыть `models.html?src=имя.json`.

## Проверка

```bash
python3 scripts/check_project.py
python3 scripts/build_notebooks.py --check   # ноутбуки в репозитории не устарели
```

`check_project.py` проверяет офлайн, без сети и зависимостей: структура и `files.json`, битые
ссылки, тип и палитра схем, наличие определений и разделов «Что мы узнали» / «Проверь себя»,
совпадение версии ассетов в трёх местах, совпадение кода в уроке с файлом лабораторной,
запуск всех лабораторных и то, что на каждый `.ipynb` ссылается хотя бы один урок.
`build_notebooks.py --check` сверяет собранные ноутбуки с исходниками в `notebooks/`.

PASS означает согласованность материалов, а не педагогическое качество: уроки всё равно нужно
посмотреть глазами в браузере.

При изменении контента поменяй `ASSET_VERSION` в `index.html` и `reader.html` (и в теге
`reader-links.js?v=` — три места должны совпадать), иначе браузер отдаст старую версию из кэша.
`check_project.py` падает, если версии разошлись.

## Публикация

Сайт: **https://ai9.adelfos.ru** — контейнер CT 109 на Proxmox `pxhome`, nginx, статика.

```bash
./deploy-pxhome.sh              # проверки + сборка + выкладка (через ssh-алиас pxhome)
./deploy-pxhome.sh --build-only # только собрать: BUILD_DIR=/tmp/site ./deploy-pxhome.sh --build-only
```

Как устроено: сайт — это ровно содержимое `docs/books`. Скрипт распаковывает релиз в
`/var/www/releases/<домен>/<дата>`, пишет vhost, атомарно переключает симлинк
`/var/www/sites/<домен>` и перезагружает nginx. Дальше — дымовые проверки (7 ключевых файлов
должны отдавать 200). Если что-то пошло не так, предыдущий релиз и vhost возвращаются
автоматически. Хранятся последние 5 релизов.

Переменные: `SITE_DIR` (домен), `CTID`, `VIA` (`host` — через хост и `pct`, по умолчанию;
`direct` — ssh прямо в контейнер, так работает CI), `CHECK=0` — пропустить проверки.

## CI/CD

| Событие | Что происходит | Где выполняется |
|---|---|---|
| push в ветку, pull request | `check_project.py` + синтаксис скриптов | облачный раннер GitHub |
| push в `main` | те же проверки, затем автоматическая выкладка | проверки — GitHub, выкладка — свой раннер в CT 121 |

Публиковать с облачного раннера нельзя: Proxmox не виден из интернета. Поэтому job `deploy`
выполняется на self-hosted раннере с меткой `ai9`, который живёт в CT 121 и ходит по LAN прямо
в CT 109.

Настройка автодеплоя (один раз, со своей машины — нужны `ssh pxhome` и авторизованный `gh`):

```bash
./scripts/setup-ci-runner.sh
```

Скрипт добавляет ssh-ключ раннера в CT 109, ставит в CT 121 второй экземпляр GitHub-раннера
(отдельный каталог `/opt/actions-runner-ai9`, отдельный сервис — существующий раннер репозитория
`web-agent` не трогается), регистрирует его на этот репозиторий с меткой `ai9` и запускает.
Повторный запуск безопасен.

Проверить раннеры: `gh api repos/iRoboTron/ai-engineering-school/actions/runners -q '.runners[].name'`

### Внешний доступ (HTTPS)

DNS на `*.adelfos.ru` уже указывает на нужный IP. Что нужно сделать в **Nginx Proxy Manager**
(CT 101) один раз:

1. Proxy Hosts → Add Proxy Host.
2. Domain Names: `ai9.adelfos.ru`; Scheme `http`, Forward Hostname `192.168.0.109`, Port `80`.
3. Включить Block Common Exploits и Websockets Support.
4. Вкладка SSL: Request a new SSL Certificate, Force SSL, HTTP/2, согласиться с Let's Encrypt.

Пока proxy host не создан, `deploy-pxhome.sh` выкладывает сайт, но честно пишет, что снаружи
он ещё недоступен.
